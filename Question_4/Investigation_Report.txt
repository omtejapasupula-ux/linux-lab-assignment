File Access and I/O Investigation Report

1. Open Files Identified:
The `lsof` command listed the open files associated with the current user (omteja). It showed the active Bash shell along with its open file descriptors and shared libraries.

2. File Descriptor Observations:
The `/proc/$$/fd` directory showed that standard input (0), standard output (1), and standard error (2) were all connected to `/dev/pts/0`. File descriptor 255 was also associated with the current terminal session.

3. Output Redirection and Error Redirection Results:
The command successfully redirected the error message generated by accessing the non-existent `/fake_directory` into `error_out.txt`. The `standard_out.txt` file remained empty because no standard output was produced.

4. Resource Limits Observed:
The `ulimit -a` command showed that the maximum number of open files is **1024**. Most other limits such as CPU time, file size, virtual memory, and core file size were set to unlimited.

5. Explanation of Linux File I/O:
Linux treats files, devices, pipes, and terminals uniformly through file descriptors. Programs read from standard input (0), write normal output to standard output (1), and send error messages to standard error (2). Redirection allows these streams to be stored in files instead of being displayed on the terminal.
