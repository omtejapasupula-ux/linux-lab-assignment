1. `lsof -u $(whoami) | head -n 15`

   - **Explanation:** This command listed the first 15 open files and processes for my current user (**omteja**). It showed the active Bash shell, its file descriptors, and the libraries currently in use.

2. `ls -la /proc/$$/fd`

   - **Explanation:** This command displayed the file descriptors for the current shell process. I observed that standard input (0), standard output (1), and standard error (2) were all linked to **/dev/pts/0**, along with file descriptor **255**.

3. `ls /fake_directory > standard_out.txt 2> error_out.txt`

   - **Explanation:** This command redirected normal output to **standard_out.txt** and redirected the error message generated by the invalid directory to **error_out.txt**, demonstrating output and error redirection.

4. `cat error_out.txt`

   - **Explanation:** This command displayed the contents of the error log file. It confirmed that the error message **"ls: cannot access '/fake_directory': No such file or directory"** was successfully redirected to the file.

5. `ulimit -a`

   - **Explanation:** This command displayed the resource limits for the current user session. I observed that the maximum number of open files was **1024**, while several other limits such as CPU time and virtual memory were set to **unlimited**.
